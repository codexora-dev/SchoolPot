# 반별 수행평가와 개인정보 운영

## 관리자 설정

1. 관리자 대시보드 → 학급·소속 관리에서 학년도와 각 학년의 마지막 반 번호를 입력합니다. 0은 해당 학년의 가입·소속 등록 중지입니다. 실제 반 수를 알 수 없어 초기값은 모두 0입니다.
2. 개인정보 설정에서 실제 개인정보처리자 명칭, 로그인 없이 이용 가능한 문의 URL, 위탁·국외 처리 및 보안 기록 보유기간을 확인해 입력합니다. 사용자 지정 명칭은 스쿨팟, 문의 URL은 https://codexora-dev.github.io/SPContact 입니다. 2026-11-12 확인 시 해당 URL은 404였습니다. 링크 자체는 공개 방침에 반영했지만 문의 접수를 제공한다고 확인한 것은 아닙니다.
3. 실제 운영 내용과 문서, 문의 수신을 확인한 뒤 검토 확인 및 동의·가입 접수 켜기를 선택합니다. 임시 문구로 접수를 켜지 마세요. 저장 시 문서 버전이 올라가며 기존 회원에게도 재동의를 요구합니다.

초기 정책은 준비 상태입니다. 운영자가 확인하지 않은 실제 운영자/처리업체/국가/보유기간을 코드가 임의로 만들어 공개하지 않습니다. 반 수와 정책 준비 전 가입은 서버에서도 거절합니다. 기존 회원은 소속·동의를 등록한 뒤 회원 서비스를 이용하며, 계정 관리·탈퇴와 개인정보 문의용 건의·오류 제보는 접근할 수 있습니다. 관리자는 미등록 상태에서도 설정을 준비할 수 있습니다.

## 소속 권한

가입 시 본인 학년·반을 선택하고 현재 문서 버전, 서버 기준 동의 시각, 14세 이상 본인 확인, 별도 위탁·국외 처리 동의를 저장합니다. 학생 실명·학번·학생증·생년월일·실제 이메일은 받지 않습니다. 연령과 소속은 자기 신고이며 실제 인증이 아닙니다. 여러 계정을 만들어 다른 소속을 신고하는 것까지 입증·차단하는 본인 인증 기능은 없습니다.

회원은 같은 학년도에서 소속을 임의 변경할 수 없습니다. 잘못 입력했으면 관리자에게 정정을 요청합니다. 관리자의 정정 사유·이전/이후 소속은 권한 검사 후 감사 기록에 남기고 회원에게 알립니다. 소속이 바뀌어도 기존 일정의 반은 자동으로 바뀌지 않습니다. 학년도가 바뀌면 회원이 새 소속을 등록합니다.

수행평가는 요청의 학년·반 대신 auth.uid()에 연결된 저장 소속으로 제한합니다. 조회·등록·수정·신고와 관리자 수정 요청 조회/처리에 동일한 반 범위를 적용합니다. 관리자도 다른 반 본문을 볼 수 없습니다. 기존 반 미지정 일정은 공개하지 않고 작성자 본인에게만 이관 메뉴를 제공합니다. 운영 중 기존 일정 1건은 삭제하지 않았습니다.

## 동의와 보유

필수 동의는 사전 선택하지 않습니다. 목적·항목·보유기간·거부권을 먼저 표시하고 전체 문서를 별도로 제공합니다. 거부 시 회원가입/회원 서비스 제한을 알리며 탈퇴로 철회할 수 있습니다. 문서 전문은 서버에서 제공하고 버전별 스냅샷을 보관해 동의 기록과 연결합니다. 정책 변경 후 재동의하더라도 같은 학년도 소속을 바꾸는 경로로 사용할 수 없습니다.

사용자 최종 결정에 따라 탈퇴 시 계정·프로필·소속·동의와 계정에 연결된 게시글·댓글·일정·문의·신고 등 작성 내용을 삭제합니다. 본인 게시글의 다른 사용자 답글도 FK에 따라 함께 삭제될 수 있음을 탈퇴 화면에 알립니다. 동의 전에도 본인 삭제·탈퇴 접근을 막지 않습니다. 과거의 탈퇴 후 본문 보존 정책보다 이 결정이 우선합니다.

이 처리는 운영 DB의 계정 연결 데이터 삭제입니다. Supabase/GitHub 등 업체의 로그·백업까지 즉시 삭제된다고 보장하지 않습니다. 가입/복구 보안 카운터는 기존 구현상 7일 경과 항목을 후속 요청 때 정리하며, 주기적 삭제 작업이 없는 상태에서 엄격한 최대 7일 보유라고 고지하면 안 됩니다. 처리방침의 별도 기록 보유·삭제 안내는 실제 계약 및 운영과 일치해야 합니다.

## 법적 검토에 남은 사항

[개인정보 보호법 제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523)에 따라 동의가 필요한 만 14세 미만 아동의 처리는 법정대리인 동의와 확인이 필요합니다. 현재는 사용자 결정대로 만 14세 이상만 가입받고 자기 확인 체크를 요구합니다. 이것은 실제 연령 인증이나 법정대리인 동의를 대신하는 기능이 아닙니다.

수집 시 고지할 목적·항목·보유기간·거부권은 [개인정보 포털 안내](https://www.privacy.go.kr/front/contents/cntntsView.do?contsNo=36)를 참고했습니다. 처리방침 공개와 책임 주체·문의 및 권리행사 경로는 실제 운영에 맞게 확정해야 합니다. 브랜드 명칭만으로 법적 책임 주체의 확인이 완료됐다고 주장하지 않습니다.

현재 Supabase 프로젝트 DB 리전은 ap-northeast-2(한국 서울)로 확인했습니다. DB 리전만으로 인증·Edge·지원·하위 처리업체와 GitHub Pages 처리가 전부 국내라고 판단할 수 없습니다. [국외 이전 고지 사항](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1033215841)을 확인하고 실제 계약·처리 위치·이전 항목/국가/시점/방법/수령자 연락처/목적/보유기간/거부 방법과 영향 및 해당 법적 근거를 검토해야 합니다. 접수 기능의 체크박스만으로 국외 이전 적법성을 확정하지 않습니다.

문의 사이트 개설, 실제 개인정보처리자 및 처리업체 정보 확정, 보안/외부 로그·백업 삭제 운영, 고지·동의 근거에 대한 운영자와 필요시 전문가 검토가 남아 있습니다. 이번 구현을 법적으로 문제없는 운영의 보증으로 표시하지 않습니다.
