# 보안 설계와 점검

## 인증·계정

실제 이메일을 수집하지 않습니다. 아이디는 내부 Supabase Auth 식별자에 매핑하며 비밀번호는 Supabase Auth가 해시로 관리합니다. accounts 서버가 8~128자를 검사합니다. 가입은 공개 경로이나 Origin·입력·DB 요청 제한을 적용합니다. 유효한 아이디 계정은 서버 전용 프로비저닝으로만 등록합니다. 공개 Auth signUp이나 user_metadata 조작으로는 account_handles에 등록할 수 없습니다.

계정 매핑과 복구 코드 해시는 private에 있고 직접 조회할 수 없습니다. 복구 코드는 암호학적 난수 256비트, 저장은 SHA-256 해시이며 원문은 가입/복구 응답에 한 번만 반환합니다. 원문을 로그·로컬 저장소·DB에 저장하지 않습니다. 코드 교체는 원자적이므로 재사용을 막습니다. 재설정 후 기존 세션을 제거하고 RPC는 매번 현재 세션을 확인합니다.

현재 로그인 계정은 Auth 사용자 존재·등록된 아이디 계정·현재 session_id·이용 제한을 DB에서 확인합니다. 역할은 private.user_roles만 신뢰합니다. 클라이언트의 role/is_admin, user_metadata는 권한 근거가 아닙니다. admin은 사용자 요청에 따라 특정 계정만 수동 지정했고 감사 기록을 남겼습니다.

자동로그인은 명시적인 선택을 받은 로그인에서만 localStorage의 Supabase 세션 토큰으로 복원합니다. 기본값은 sessionStorage이며 비밀번호·복구 코드는 보관하지 않습니다. 이전 버전의 선택 없는 영구 토큰은 새 로그인 전 복원하지 않고 정리하므로 업데이트 후 한 번 다시 로그인해야 할 수 있습니다. 자동로그인 해제/로그아웃/탈퇴 시 영구 인증 정보와 선택을 정리하며 사이트 테마·팝업 선호도는 유지합니다. 저장소 접근 차단/용량 부족 시 탭 저장 또는 현재 페이지 메모리로 대체하고 자동로그인 유지 불가를 알립니다.

회원탈퇴는 계정 메뉴와 프로필에서 접근할 수 있고 확인 문구·현재 비밀번호를 요구합니다. delete-account Edge Function이 현재 세션·계정·요청 제한과 비밀번호 재인증을 확인하고 전역 세션 취소 후 계정을 삭제합니다. UI는 실제 완료 응답 전 성공을 표시하지 않고, 중복 제출과 처리 중 닫기를 막습니다. 탈퇴 완료 후 로컬 인증 토큰·자동로그인 선택·개인 임시 글을 정리합니다. 서버 함수와 DB 권한 설계는 이번 UI 작업에서 변경하지 않았습니다.

## DB·익명성

모든 데이터 테이블은 private 스키마, RLS 활성화, anon/authenticated 직접 권한 회수, 허용 정책 없음의 기본 거부입니다. public.community invoker 래퍼가 private definer 디스패처를 호출하며 모든 작업에서 인증/소유권/관리자 검사를 수행합니다. public.account_gateway는 service_role만 실행할 수 있습니다. 함수 search_path는 비우고 정적 SQL과 완전 수식 이름을 사용합니다.

글/댓글 응답은 화이트리스트로 구성합니다. UUID·계정 매핑·이메일·안정적인 익명 ID를 반환하지 않고 글별 번호만 제공합니다. 내 글 여부는 boolean입니다. 관리자 신고 조회만 처리에 필요한 대상 ID를 반환하며 감사 기록을 남깁니다. 본문에 사용자가 스스로 남긴 개인정보를 자동으로 지우는 기능은 아닙니다.

## 요청·브라우저

사용자 텍스트는 텍스트 노드로 렌더링합니다. innerHTML/eval/실행 가능한 Markdown을 사용하지 않습니다. SQL 바인딩·CHECK·FK·복합 PK로 입력 길이, 소유권, 중복 공감/투표를 보호합니다.

일반 RPC는 180회/분, 글 10회/10분, 댓글 30회/10분, 공감 60회/분, 신고 10회/시간, 일정 15회/시간을 제한합니다. 성공 트랜잭션 기준이므로 WAF 대체가 아닙니다. 공개 가입/복구는 별도 IP 해시·아이디·전역 버킷을 사용합니다. 원본 IP는 저장하지 않으며 서비스 비밀값을 넣은 해시로 의사식별합니다. 가입 전역 300회/시간, IP 10회/시간, 아이디 6회/15분입니다. 학교 공유 IP에 맞춘 운영 조정이 필요할 수 있습니다. 복구는 전역 300회/15분, IP 20회/15분, 아이디 6회/15분입니다. 카운터는 7일 이상 된 항목을 정리합니다.

Edge 본문은 스트림 읽기 중 4096바이트로 제한합니다. NEIS는 고정 HTTPS 호스트만 사용합니다. 학교 이름/코드는 공개 설정, NEIS 키와 Supabase service_role은 서버 런타임에만 존재합니다. 프론트 secret 키는 빌드 전에 거절합니다.

Cloudflare/Vercel용 CSP·frame-ancestors·nosniff·HSTS·권한 제한을 제공합니다. Pages용으로 빌드에 CSP meta를 삽입하나 헤더 전용 frame-ancestors 정책은 별도 호스팅이 필요합니다. 외부 분석·원격 폰트·학생증 수집은 없습니다.

## 탈퇴·개인정보

탈퇴는 현재 비밀번호로 재인증 후 세션을 전역 로그아웃하고 Auth admin API로 사용자를 삭제합니다. 프로필·역할·계정 매핑·공감·투표·알림은 삭제하고 본문/신고/감사 기록의 계정 연결은 NULL로 만듭니다. 글과 댓글은 탈퇴 전 직접 삭제할 수 있습니다. 이용 제한 회원도 본인 프로필 확인과 탈퇴는 가능합니다.

닉네임·선택 학년과 서비스 활동만 앱에 저장합니다. 로그인 세션과 임시 글은 사용자 기기에 있으므로 공용 기기에서 로그아웃해야 합니다. 서버 Auth 로그·백업, 신고/감사 기록과 본문 개인정보의 보존기간은 운영자가 확정해야 합니다. 약관·개인정보 처리방침·운영자 연락처·연령/동의와 코드 분실 시 본인 확인 정책은 임의로 확정하지 않았습니다.

## 결과

실제 서버와 브라우저 검증을 포함한 결과는 verification.md를 참고하세요. 최신 Security Advisor에는 기본 거부 RLS의 no policy INFO 29건과 Auth 유출 비밀번호 보호 비활성 WARN 1건이 있습니다. [해당 Advisor 설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)을 참고하되 불필요한 허용 정책을 추가하지 마세요.

## 반별 수행평가·소속과 동의

소속은 private.memberships에 저장하고 auth.uid()와 현재 학년도·실제 반 범위로 확인합니다. 정책 버전이나 동의는 접근 조건이 아닙니다. 요청의 학년·반을 권한에 사용하지 않으며 일반 회원의 같은 학년도 소속 변경과 프로필 필드를 통한 우회를 금지합니다. 관리자도 다른 반 수행평가 본문·수정 요청은 조회/처리할 수 없습니다. 소속 정정은 관리자만 수행하고 이전/이후 값과 사유를 감사 기록에 남깁니다.

school_setup의 공개 예외는 반 수·학년도·현재 정책 전문과 공개 문의 연락처뿐입니다. 문서는 서버 버전별 스냅샷에 보관합니다. 가입 Edge가 Auth 생성 전에 연령 본인 확인·학급 범위를 검증하고 소속 기록 실패 시 부분 생성 계정을 삭제합니다. 신규 가입·기존 회원 등록은 동의 체크나 문서 검토 상태를 요구하지 않습니다. 새 기록의 동의 시각은 null이고 기존 동의 기록의 원래 버전은 보존합니다. 14세 체크는 자기 신고이며 신원·연령·재학생을 입증하지 않습니다.

최신 보유 결정에 따라 Auth 사용자 삭제 전 계정 연결 작성 내용·소속·동의를 삭제합니다. 기존 본문 보존 정책보다 우선하며 본인 게시글의 타인 답글도 삭제될 수 있습니다. 외부 로그·백업·보안 카운터까지 탈퇴 즉시 모두 삭제됐다고 주장하지 않습니다. 실제 문의 경로와 위탁·국외 처리 등 남은 운영 검토는 classes-privacy.md를 따릅니다.

## 사이트 진입 팝업

공개 안내만 site_popups RPC로 비회원 조회할 수 있습니다. private 테이블의 직접 권한은 계속 거절하며, 제목·본문·닫기 옵션·버전·팝업 ID만 반환합니다. 작성자 UUID, 중지된 팝업, 관리자 기록은 반환하지 않습니다. manage_popups는 private.community의 실제 계정·세션·역할 검사와 이용 제한 검사를 거치고 요청 제한·기본 닫기 강제·동시 게시 제한·오래된 수정 차단·감사 기록을 적용합니다. 공개 안내 읽기 예외는 일반 커뮤니티 데이터에 적용되지 않습니다.

## 게시판과 비공개 문의

board_catalog는 기존 공개 메뉴와 같은 운영 중 게시판 메타데이터만 공개합니다. 숨김 게시판은 관리자 권한 검증을 거친 manage_boards 목록에만 표시합니다. 게시판 변경은 버전 검사·감사 기록·요청 제한을 적용합니다. 쓰기 요청은 게시판 행 공유 잠금을 사용해 상태 변경과 직렬화하며, 일반 회원의 읽기 전용/숨김 글·댓글·공감·투표 요청을 거절합니다. 작성자의 본인 글 삭제는 계속 허용합니다. 주소와 유형은 생성 후 고정하며 사용자 정의 익명 게시판에도 서버 익명을 강제합니다.

feedback API의 작성자 값은 auth.uid()로만 정합니다. 본인 목록은 author_id 조건으로 강제하며, 관리자 목록·답변은 현재 DB 역할과 감사 기록을 요구합니다. 본문·답변은 textContent로 렌더링하고 직접 테이블 권한은 거절합니다. 요청의 소유자·상태·답변 위조, 타인 문의 ID 조회, 세션 삭제 후 JWT 재사용, 동시 수정 덮어쓰기 등을 DB 테스트와 실제 API로 검증했습니다.

[유출 비밀번호 보호 설정](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) 비활성 WARN 1건도 확인했습니다. 팝업과 별개인 Auth 설정이며, 공식 문서상 Pro 이상 기능이므로 임의의 유료 플랜 변경은 하지 않았습니다.
