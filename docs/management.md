# 게시판과 문의 관리

## 게시판

관리자 대시보드 → 게시판 관리에서 새 게시판을 추가하거나 기존 게시판을 수정합니다. 주소는 영문 소문자로 시작하는 영문·숫자·하이픈 3~32자, 이름은 2~40자, 설명은 최대 160자입니다. 작은 표시 순서가 먼저 나오며 같은 순서에서는 주소로 정렬합니다. 최대 50개 게시판을 관리할 수 있습니다.

- 일반: 작성자가 익명 여부를 선택합니다.
- 항상 익명: 클라이언트 설정과 관계없이 서버에서 익명을 강제합니다.
- 투표: 새 글에 2~6개 선택지를 작성합니다.

생성 후 주소와 유형은 바뀌지 않습니다. 이름을 바꿔도 기존 글과 익명 설정은 유지합니다.

- 운영 중: 회원이 읽고 글·댓글·공감·투표를 작성할 수 있습니다.
- 읽기 전용: 기존 글은 읽을 수 있지만 새 작성·수정·공감·투표는 멈춥니다.
- 숨김: 일반 메뉴·검색에서 제외하며 다른 회원은 글 주소로도 접근할 수 없습니다. 작성자는 자신의 글을 조회·삭제할 수 있습니다.

관리자는 모든 상태에서 게시판 열기로 확인하고 관리할 수 있습니다. 회원 본인 삭제와 신고는 읽기 전용에서도 허용합니다. 게시글이 있는 게시판은 삭제할 수 없습니다. 빈 게시판 삭제에는 확인 창이 표시됩니다. 운영 상태는 서버가 다시 검증하므로 오래된 화면이나 직접 RPC 요청으로 우회할 수 없습니다.

## 건의·오류 제보

로그인한 회원은 주 메뉴·계정 메뉴·모바일 게시판 목록의 건의·오류 제보에서 건의사항, 오류 제보, 기타 문의를 보냅니다. 제목 2~120자, 본문 최대 8,000자이며 시간당 최대 5건을 접수합니다. 실명·학번·연락처·비밀번호·복구 코드는 요청하지 않습니다. 내용을 작성할 때도 넣지 않도록 안내합니다.

작성자는 내 문의에서 자신의 문의만 최신순으로 20건씩 확인합니다. 관리자는 대시보드 → 건의·오류 관리에서 유형과 상태로 조회하고 최대 4,000자 답변을 저장합니다. 상태는 접수, 확인 중, 해결 완료, 종료입니다. 답변 또는 상태가 달라지면 알림 수신을 켠 작성자에게 사이트 내 알림이 전달됩니다. 이메일은 사용하지 않습니다.

관리자 조회와 처리 작업은 감사 기록을 남깁니다. 동시 수정으로 답변을 덮어쓰지 않도록 버전을 검사하며, 충돌 시 목록을 다시 불러와 처리합니다. 다른 회원의 문의나 작성자 UUID를 API 응답에 노출하지 않습니다. 탈퇴 시 작성자 계정 연결은 제거되며 문의 본문은 관리자 처리 기록으로 남습니다.

## DB와 검증

게시판 정보는 기존 private.boards를 확장하며 문의는 private.feedback에 저장합니다. 두 테이블 모두 RLS와 직접 접근 권한 회수를 유지합니다. public invoker RPC → private definer의 인증·현재 세션·등록 계정·이용 제한·소유권·역할 검사로 접근합니다. 공개 board_catalog에는 운영 중인 게시판 메타데이터만 포함하며 글·댓글·문의·숨김 게시판은 포함하지 않습니다.

관련 마이그레이션은 20261112121308_board_management_feedback.sql입니다. 로컬 PostgreSQL 권한 테스트와 UI fixture 테스트, 실제 Supabase의 임시 QA 계정 API 검증은 구분해 verification.md에 기록합니다. 실제 검증 스크립트는 tests/integration/management-live.mjs이며 임시 역할 부여·문의 정리 단계는 운영 도구에서 정확한 QA 계정만 대상으로 수행해야 합니다. 실제 사용자 계정의 권한이나 데이터를 변경하지 마세요.
