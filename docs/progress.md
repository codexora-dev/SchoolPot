## 요구사항 변경

사용자가 재학생 인증 신청 없이 회원가입하도록 변경했다. 신청 테이블·신청 UI·자동 승인·학생증 수집 없이 이메일 인증 회원제만 구현했다. 안내에도 재학생 확인을 하지 않는다는 점을 명시했다.

## 발견한 문제와 해결

1. 초기 ESLint 10 의존성에서 minimatch 관련 moderate 취약점 4건 확인. 취약점이 없는 ESLint/@eslint/js 9.39.5 조합을 고정하고 lockfile을 저장했다. ESLint 9의 지원 종료 경고는 남아 있으므로 향후 ESLint 10 의존성 수정 확인 후 업그레이드한다. npm audit은 현재 0건이다.
2. 수행평가 UI 초기 중첩 DOM 표현의 괄호 오류를 빌드에서 발견하고 반복문 기반 생성으로 정리했다. 재빌드/린트 통과.
3. Playwright 실행용 브라우저 미설치로 첫 실행 실패. Chromium을 설치한 뒤 재실행해 통과했다.
4. 댓글 응답을 페이지당 50개로 제한하고 이동을 추가했다. 탈퇴 후 남은 토큰을 계정 존재 확인으로 거절하도록 구현했다.
5. 이용 제한 회원이 탈퇴할 수 있도록 me/delete_account_access에 한해 제한 검사를 예외 처리했다. 커뮤니티 접근은 계속 거절한다.
6. 빈 토스트가 첫 캡처에서 잠깐 보일 수 있어 :empty는 숨기도록 처리했다. 아이콘 버튼에 접근성 레이블을 추가했다.
7. Supabase 도구의 프로젝트 접근 권한 오류 발생. 권한을 우회하거나 서비스 키를 요청하지 않고 로컬 구현을 계속했다. 전달받은 공개 키로 원격 RPC의 미설치(PGRST202)를 확인했으며 DDL은 실행하지 않았다.

## 최종 검증 항목

실행 명령 및 최종 수치는 작업 완료 시 `verification.md`에 기록한다. UI 회원/관리자 테스트는 테스트 전용 Supabase 네트워크 fixture를 사용하며 제품 코드에는 fixture가 없다. DB 테스트는 실제 PostgreSQL 엔진(PGlite)에서 SQL 함수와 역할/제약조건을 실행한다.

다음 작업: 원격 스키마 검토·마이그레이션 적용, Auth/SMTP 설정, 실제 학교 정보와 NEIS 키 설정, 최초 관리자 지정, Edge 배포, 원격 보안/기능 재검증, 운영 정책 확정 후 승인된 외부 배포.

## 아이디 계정 및 실제 서비스 연동 업데이트

사용자 요청으로 이메일 인증을 제거하고 아이디/8자 이상 비밀번호 가입·로그인으로 전환했다. 계정·복구 코드는 서버 전용 프로비저닝, 복구 해시는 비공개 저장, 재설정 후 코드/세션 무효화를 적용했다.

실제 프로젝트에 기본 DB 및 아이디 계정 마이그레이션 3개와 Edge Function 3개를 적용했다. Auth admin 생성 시 메타데이터 적용 시점 차이를 실제 가입 실패로 발견하여 후속 프로비저닝 마이그레이션으로 해결했다. 실제 UI 탈퇴 직후 세션 이벤트 경합도 수정했다.

안남중학교(S10/9022150) NEIS 실응답을 연결했다. 실제 API 15개와 실제 화면 흐름 검증 1개를 통과하고 QA 데이터를 정리했다. 사용자 지정 admin 계정만 관리자 부여 및 감사 기록을 남겼다. 전체 최신 결과는 verification.md 기준이다.

## 2026-11-12 반응형 GUI·저장소 이름 변경·빈 화면 복구

SchoolPot으로 Git origin과 문서를 변경했다. 저장소 이름 변경 후 기존 HTML이 /SchooltPot/assets를 참조해 JS/CSS 404가 발생했고, 사용자는 본문 바로가기 링크만 보았다. 새 이름으로 재빌드하여 실제 자산 200을 확인했다. 이후 main 프론트엔드 변경 자동 배포와 배포 후 빌드/자산 검사를 추가했다.

UI는 PC 사이드바/태블릿 아이콘 메뉴/모바일 하단 메뉴로 분리하고 글자·입력·터치 영역·카드·SVG 아이콘을 정리했다. 모바일 검색 모달, 레이아웃을 밀지 않는 계정 메뉴, 비밀번호 보기, Escape/외부 클릭 닫기, 본문 포커스와 투표 입력 조건부 표시를 구현했다. CSS는 토큰/레이아웃/컨트롤/페이지/반응형으로 나눴다.

Supabase에는 public 대신 private 스키마에 23개 테이블이 있음을 확인했고, posts/profiles의 실제 저장 건수를 읽기 전용으로 확인했다. 운영 데이터는 변경하지 않았다. CI 설치 실패는 azure.archive.ubuntu.com DNS 문제였으며 기본 Chrome을 사용하도록 수정했다. 최신 검증 결과는 verification.md에 기록했다.

## 2026-11-12 관리자 사이트 진입 팝업

사이트 진입 팝업 등록/수정/중지/재개/삭제·미리보기와 기본/오늘 하루/다시 보지 않기 옵션을 구현했다. public projection은 게시된 제목·본문 등 최소 필드만 반환하고, 관리 API는 기존 인증·세션·계정·관리자 권한과 요청 제한을 재사용한다. RLS·작성자 비노출·기본 닫기 강제·최대 3개 활성 팝업·오래된 수정 거절·감사 기록을 적용했다.

DB 마이그레이션을 원격 적용하고 비회원 조회 200/관리 거절 401을 확인했다. 로컬 입력/선호도 15개, DB 48개, 브라우저 30개를 통과했다. 실제 임시 QA 계정으로 일반 권한 거절·비공개 생성·수정·버전·옵션 검증·삭제 7개를 통과하고 계정/팝업 잔여 0건을 확인했다. 활성 공개 조회는 실제 DB 역할 및 롤백 트랜잭션으로 검증해 방문자에게 테스트 내용을 게시하지 않았다.

같은 페이지를 자정 너머 유지할 때 오늘 하루 설정이 만료될 수 있도록 지속 저장 성공 시에는 방문 메모리로 중복 숨김하지 않게 했다. 관리자/방문자 테스트 fixture와 실제 서버 검증을 분리했다. Security Advisor에서 Auth 유출 비밀번호 보호 비활성 WARN 1건을 새로 확인하여 문서화했으며 유료 설정을 임의 변경하지 않았다.

## 2026-11-12 게시판 관리·건의 및 오류 제보

관리자 게시판 추가/수정/정렬/읽기 전용/숨김/빈 게시판 삭제와 일반·항상 익명·투표 유형을 구현했다. 주소·유형은 생성 후 고정하고 기존 글이 있으면 삭제를 거절한다. 메뉴와 작성 화면은 DB 메타데이터를 사용하며 로딩 실패를 정적 가짜 목록으로 숨기지 않는다. 서버에서 게시판 상태를 검사하고 공유 행 잠금으로 관리자 상태 변경과 쓰기를 직렬화한다. 숨김 게시판은 일반 목록/검색/타인 직접 조회에서 제외하고 작성자의 본인 삭제는 유지한다.

회원 전용 건의·오류 제보 및 내 문의, 관리자 유형/상태별 목록·답변·상태 처리, 변경 알림과 미처리 문의 현황을 추가했다. 문의는 private.feedback + RLS + 직접 권한 회수로 저장하며 작성자와 관리자만 조회한다. 소유자/역할/처리 상태 위조 차단, 버전 검사, 요청 제한, 감사 기록, textContent 렌더링을 적용했다. 공개 board_catalog는 기존 공개 메뉴와 같은 운영 중 메타데이터만 제공하고 숨김 게시판·글·댓글·문의는 제외한다.

초기 SQL 검증에서 관리자 목록의 별칭과 행 변수 이름 충돌을 발견해 별칭을 분리했다. 새 선택 메뉴의 접근성 이름이 옵션까지 포함되던 문제는 명시적인 레이블로 수정했다. 긴 모바일 문의 처리 창이 실제 뷰포트 안에 들어가는지 확인했고, fullPage 캡처의 대화상자 위치 왜곡을 피하려 뷰포트 캡처로 저장했다.

원격 스키마 선조사 후 마이그레이션을 적용했다. lint·단위 15개·PGlite DB 61개·Playwright fixture 35개·build를 통과했다. 실제 Supabase API 7개 검사에서는 임시 QA 계정 2개로 문의 격리/답변/알림과 비공개 게시판 CRUD/접근 제한을 검증했다. QA 데이터 잔여 0건, private 전체 RLS 활성화를 확인했다. 실제 방문자에게 테스트 게시판을 공개하지 않았고 운영자 admin 역할이나 기존 글은 변경하지 않았다.

Security Advisor는 의도적인 기본 거부 no policy INFO 25건과 기존 Auth 유출 비밀번호 보호 비활성 WARN 1건이다. 운영 안내는 management.md, 최신 검증은 verification.md에 기록했다. 코드의 main 반영 및 GitHub Pages 최종 배포 검증을 진행한다.
